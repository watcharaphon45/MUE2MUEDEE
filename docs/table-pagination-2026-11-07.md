# Pagination และความกว้างตาราง — 7 พฤศจิกายน 2026

## พฤติกรรมร่วม

- เลือก 10, 15, 20, 25, 50 หรือ 100 รายการต่อหน้า พร้อมช่วงรายการ จำนวนทั้งหมด ปุ่มหน้าแรก/ก่อนหน้า/เลขหน้า/ถัดไป/สุดท้าย
- หน้ารายการคลังและรับซื้อเริ่ม 15 รายการ, ใบขายเริ่ม 25 รายการ, ร้านค้าออนไลน์เริ่ม 50 รายการ
- เปลี่ยนจำนวนแถวหรือผลการกรองแล้วเริ่มหน้าแรก; การแก้เนื้อหาแถวที่มี ID เดิมไม่ทำให้หน้ากระโดด
- API pagination ไม่ตัดข้อมูลซ้ำใน browser และระงับปุ่มขณะโหลด
- POS ใช้ index ของสินค้าในบิลจริงเมื่อแก้ส่วนลด/ลบแถวบนหน้าที่ 2 เป็นต้นไป ยอดรวมยังรวมทั้งบิล
- รายการ checkbox ในคลังล้างการเลือกเมื่อเปลี่ยนหน้า เพื่อให้จำนวนที่เลือกตรงกับรายการสำหรับพิมพ์สติ๊กเกอร์
- คอลัมน์ชื่อและรายละเอียดตัดบรรทัดได้, Serial/รหัสยาวแบ่งบรรทัดได้, เงินชิดขวาและไม่ตัดกลางจำนวน, วันที่/สถานะ/ปุ่มใช้พื้นที่ตามเนื้อหา
- บนจอเล็ก ตารางที่มีหลายคอลัมน์เลื่อนแนวนอนภายในกรอบได้ โดยไม่ขยายหน้าทั้งหน้า
- ตัวเลือกจำนวนแถวใช้ CDK overlay จึงไม่ถูกกรอบตารางหรือ card ตัดบัง รวมถึงตารางว่าง
- ตารางใบพิมพ์ 2 ตารางคงรายการครบทุกชิ้น และไม่แสดงตัวแบ่งหน้าบนเอกสาร

## การตรวจสอบ

```powershell
# รันใน mue2muedee/src/Mue2MueDee.Web/spa/
npm.cmd test -- --watch=false
npm.cmd run check:tables
npm.cmd run build -- --configuration development
npm.cmd run check:tables:browser
npm.cmd run build
```

- ชุดทดสอบ Frontend 24 รายการ: รวมขอบเขตหน้า, ตารางว่าง, เปลี่ยนจำนวนแถว, การกรอง, API pagination, loading, การแก้และลบสินค้า POS ทั้ง desktop/mobile
- `check:tables` ตรวจตารางใช้งาน 20 ตารางและตารางใบพิมพ์ 2 ตาราง เพื่อจับตารางที่ยังไม่เชื่อม Pagination หรือไม่มีรูปแบบคอลัมน์
- Browser checks ใช้ Chrome/Edge แบบ headless กับเว็บไซต์และ HTTP API จำลองในเครื่อง ตรวจ 19 หน้า/แท็บบน 2 ขนาดจอ รวม 38 หน้าทดสอบ พร้อมเปลี่ยนหน้าและเลือกจำนวนแถวจริง และตรวจเมนูจำนวนแถวของตารางว่างเพิ่มเติม
- ภาพตัวอย่างและผล browser อยู่ที่ `spa/.angular/table-ui-check/` ซึ่งไม่รวมใน Git

การทดสอบ browser ไม่เชื่อมฐานข้อมูลร้านค้า ไม่ส่งคำสั่งซื้อขาย และไม่ใช้ profile browser ส่วนตัวของผู้ใช้
